**How a seam is held:** a Vite plugin in our wrapper answers chosen module ids with our file (`ProviderInstanceIcon`,
`ChatHeader` resolve to ours). The two small patches (the sidebar slot, the right-panel kinds) live as `patches/*.patch`,
applied on each update. A nightly job pulls upstream, applies them, builds, runs a smoke test and says so before Shaan
sees a break.

## The hard part: the agents

Today an agent is a **herdr pane** (Claude Code or Codex in a terminal); Agent Zero, the owners, the fleet board and the
tasks all read herdr. In T3 an agent is a **thread** that the T3 server runs through the SDK. Three ways to join them:

1. **New work in T3, the fleet stays in herdr (start here).** New chats are T3 threads; herdr agents show in our sidebar
   section and open our current chat. Nothing breaks; two kinds of chat for a while.
2. **A herdr provider driver.** T3's adapter interface (`provider-core/src/server/adapterDriver.ts:35-49`, registered in
   `builtInProviderAdapterDrivers.ts`) wraps an outside process: a `herdr` driver makes each pane a T3 thread. Deep work,
   our own code, no upstream edits.
3. **Move the fleet to T3 threads.** Agent Zero and the owners start as T3 threads on the mini's T3 server; herdr retires
   for chat. The biggest change; only after 1 proves itself.
